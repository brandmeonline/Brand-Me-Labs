## Per-component diagnosis (most-default axis = Phase B lever)

### `app/layout.tsx` — score 0 (page-shell)
**Most-default axis: everything.** The shell is Inter on bg-black with a 12-col centered main. This is what every Next.js starter template ships. The shell is also the highest-leverage surface — typography family, vertical rhythm, max-width, background treatment all cascade from here. **Phase B lever: pick a display face + a body face + a non-centered container strategy.**

### `components/Header.tsx` — score 1 (navigation)
**Most-default axis: typography.** The wordmark is `text-2xl font-bold`, the nav is `text-sm font-medium`. The integrity pill (the one element with intent) is the only thing distinguishing this from a stock e-commerce header. A luxury platform's header should let typography do the work — display face wordmark, oversized or microscopic nav, no rounded pill. **Phase B lever: wordmark typography + nav rhythm.**

### `components/GarmentCard.tsx` — score 3 (card)
**Most-default axis: typography + grid.** Aspect ratio is right (3:4 for garments) but the title is `text-lg font-semibold` over a gray block. Every shadcn product card on the internet looks identical. The status corner-pill is the only distinctive moment. A garment authentication card needs the *certificate* feeling — type as content, image as evidence, not "product tile." **Phase B lever: typography hierarchy + how the verification state inhabits the card (corner pill vs. inhabiting the type vs. embossed/sealed treatment).**

### `components/FacetList.tsx` — score 3 (list)
**Most-default axis: surface.** Has good typographic intent (uppercase tracking-wide labels, left-rule indent rail) but renders as flat dark cards. Provenance facets are *evidence* — they want to read as document, certificate, or pinboard, not as another stack of gray panels. **Phase B lever: surface treatment (paper-like, lined, indexed, or stamped).**

### `components/IntegrityBadge.tsx` — score 5 (dashboard tile) ⭐ highest current score
**Most-default axis: density.** Best component in the system. Handmade tri-state, tonal restraint, font-mono for hashes. But the box itself is still a default card — `bg-green-900/20 border rounded-lg p-4`. For *the* brand-defining verification moment, this should be a seal, a stamp, or a certificate strip — material, not a card. **Phase B lever: surface (dimensional/material) + density (compress or expand deliberately, not card-default).**

### `app/stash/page.tsx` — score 0 (page)
**Most-default axis: header treatment + empty state.** Just a `text-5xl Your Stash` over a 1/2/3 grid of GarmentCards. The empty state is a centered paragraph. Inherits from GarmentCard. **Phase B lever: page-level typography rhythm (a "Stash" feels personal — it could be diary-typed, ledger-formatted, or wardrobe-indexed).**

### `app/shop/page.tsx` — score 0 (page)
**Most-default axis: hero typography.** `text-5xl Discover` + paragraph + grid. Identical structural shape to stash. **Phase B lever: same as stash + grid break (asymmetric, magazine-paginated, runway-strip).**

### `app/scan/page.tsx` — score 3 (page — passport view) ⭐ highest leverage
**Most-default axis: grid.** This is where someone learns what Brand.Me is — a garment passport. Currently single-column max-w-2xl with a hero image, badge, facet list, two CTAs. That's a stock product detail page. A passport is a *document* — multi-column, marginal annotation, stamps, footers. The brand opportunity is enormous and the current execution gives it away. **Phase B lever: layout grid (certificate / passport / lookbook spread vs. SaaS centered column).**

### `app/governance/page.tsx` — score 0 (operator console)
**Most-default axis: literally everything — it's a stock SaaS admin table.** `px-6 py-3` thead, green/red action buttons, `bg-gray-900` rows. This is an operator surface so it doesn't need to be luxury, but it could read as *court ledger / case file / industrial control room*, not Notion-admin. **Phase B lever: primitives (court-record / case-file / ops-console aesthetic instead of CRUD table).**

## Phase B candidates

All 9 surfaces qualify (every score ≤6). However running 9 × 3 anchors = 27 refiner calls produces low-density output that won't be read carefully. Prioritizing by **leverage** (how much of the system inherits from this surface):

### Tier 1 — Run Phase B now (6 candidates × 3 anchors = 18 concepts)

These are the surfaces where design choices cascade into the rest of the system:

1. **`IntegrityBadge.tsx`** — the brand-defining claim, appears in every passport. Highest leverage per pixel.
2. **`app/scan/page.tsx`** — the passport canvas; biggest opportunity to show what a Brand.Me document actually is.
3. **`components/GarmentCard.tsx`** — primary commerce unit, repeats on shop + stash.
4. **`components/FacetList.tsx`** — provenance reading surface, repeats in every passport.
5. **`app/layout.tsx`** — site spine; typography + container strategy cascades everywhere.
6. **`components/Header.tsx`** — sets tone on every page.

### Tier 2 — Defer Phase B (3 candidates)

These largely *inherit* from Tier 1 and will partially redesign themselves once Tier 1 ships:

7. **`app/stash/page.tsx`** — inherits from GarmentCard + layout
8. **`app/shop/page.tsx`** — inherits from GarmentCard + layout
9. **`app/governance/page.tsx`** — distinct aesthetic problem (operator vs. consumer); worth a dedicated Phase B run *after* Tier 1 ships, with a different anchor mix (drop Aesop, add `arena-brutalist` / `bloomberg-bw` / `linear`).

## Anchor strategy for Tier 1

Per `references.md`, default Brand.Me triad: **`linear`** (credibility) + **`aesop`** (luxury) + **`family-co`** (soul).

Component-specific overrides:
- `IntegrityBadge.tsx` → swap `family-co` for **`vacheron-watch-archive`** (heritage-certificate aesthetic — this is exactly the problem)
- `app/scan/page.tsx` → swap `linear` for **`vacheron-watch-archive`** (it's a passport, not a SaaS dashboard)
- `components/GarmentCard.tsx` → triad as-is (the strongest test of the default triad)
- `components/FacetList.tsx` → swap `linear` for **`are-na`** (text-first list-as-evidence)
- `app/layout.tsx` → triad as-is
- `components/Header.tsx` → swap `family-co` for **`the-row`** (radical reduction is the most powerful header move)
